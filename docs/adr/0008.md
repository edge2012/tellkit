# 0008 — Measure route latency

**Context.** A slow first response can come from the route even when application handlers are fast. The tunnel selected Los Angeles edges and cross-border time to first byte reached 1.2–2.4 seconds. This made browser waiting time a poor standalone measure of the application’s own processing cost.

**Alternatives.** One route starts by optimizing handlers and database work. The other measures origin response and delivery response separately, then inspects relay geography and transport. Changing the tunnel to protocol: http2 was tried and did not help; absent IPv6 connectivity also constrained the available route choices.

**Decision.** Choose network-path measurement before changing application logic when the delivery response includes a distant relay. Moving ingress to Hong Kong, with Caddy and an SSH return tunnel, changed time to first byte from 2.42 seconds to 0.38 seconds. The useful comparison is the same delivery operation across the two routes.

**Consequences.** Route measurements need consistent request conditions and clear separation from render duration. A fast edge response alone does not establish sustained media throughput, and a healthy origin does not establish browser reachability. Retest the delivery path after routing changes so a later regression can be assigned to the correct boundary.
