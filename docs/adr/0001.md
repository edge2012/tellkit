# 0001 — Authenticated object reads

**Context.** A rendered movie is an account-owned object, even when it is short enough to circulate as a link. The example movie contains 480 frames over 16 seconds. Its duration does not change the authorization question: possession of a storage address must not silently become permission to read another account’s result.

**Alternatives.** One route exposes object storage directly and lets the address act as the access mechanism. The other checks the requesting account against the object before issuing an expiring signed link. Direct exposure simplifies playback integration, but it leaves ownership enforcement outside the request that grants access.

**Decision.** Choose scoped authorization followed by a signed link. Check ownership before signing, and issue the link for the requested object rather than granting broad storage access. The decision separates the account’s durable entitlement from the temporary capability used by the media client, so link renewal has a clear authorization boundary.

**Consequences.** Expiration introduces renewal handling and can interrupt a client that waits too long before playback. A signed link can also be forwarded while valid, so its lifetime matters. Delivery diagnostics must distinguish an expired capability from an unavailable object; neither condition should trigger a new render automatically.
