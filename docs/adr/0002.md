# 0002 — Delivery ingress

**Context.** The delivery route moved from direct origin access to Cloudflare Tunnel. All selected edge nodes were in Los Angeles, and cross-border time to first byte was 1.2–2.4 seconds. The application could be healthy while the browser still waited on a geographically unsuitable network path.

**Alternatives.** One route kept the managed tunnel and tried transport changes. Setting protocol: http2 did not resolve the delay, and the host had no IPv6 connectivity. The other route placed TLS termination on a Hong Kong edge machine and used an SSH tunnel to reach the origin.

**Decision.** Choose the Hong Kong edge with Caddy terminating TLS and SSH carrying origin traffic. Time to first byte changed from 2.42 seconds to 0.38 seconds after the route change. That reduction supplied a concrete reason to replace the earlier tunnel arrangement: the browser’s waiting time improved by changing ingress geography.

**Consequences.** The replacement adds an edge machine, certificate handling and tunnel lifecycle management. Reachability now depends on both the edge and its connection to the origin. Diagnose those boundaries separately, and retain a way to test origin health without mistaking a disconnected tunnel for a failed application.
