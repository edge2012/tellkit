# 0016 — Keep evidence outside source distribution

**Context.** A source distribution needs enough evidence for a reader to exercise the renderer and inspect its result. The bundled example renders 16 seconds into 480 frames at 1280×720. That is a concrete, bounded exercise: the input can be read, the movie watched and the encoded action checked without navigating an entire historical archive.

**Alternatives.** One route bundles every accumulated acceptance artifact with the source. The other includes a reproducible example and keeps the broader evidence collection separately. Full inclusion preserves proximity but makes the repository harder to inspect, while a small example offers a clear connection between input declarations and visible output.

**Decision.** Choose the small reproducible example with render code, fixed input and locally generated evidence. Preserve the connection between a movie and its own diagnostic records rather than copying unrelated evidence into the release. Use multiple frames from the same 16-second movie when presenting its behavior, because one still image cannot demonstrate a temporal action.

**Consequences.** The example covers its own board and output format; broader claims require additional cases. Separate evidence storage needs retention and discovery rules if those cases must be investigated later. Readers gain an executable starting point but must build their own acceptance set when adding shapes, actions or instructional content beyond the included example.
