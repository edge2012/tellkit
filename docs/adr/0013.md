# 0013 — Carry validation results to delivery

**Context.** Fact checking ran, but its result was not persisted, and the movie was still sent. The failure was not an absent check invocation; it was a broken handoff between checking and delivery. A successful render and a completed check process did not establish that the recipient received an accepted version.

**Alternatives.** One route records checking as a log event and lets delivery proceed from the movie’s existence. The other treats the saved checking result as a required artifact associated with the same version. Logging is useful for diagnosis, but it cannot replace the result consumed at the delivery boundary.

**Decision.** Choose version-bound delivery of the fact-check result. Missing factcheck.json means the delivery is incomplete, even if encoding and upload succeeded. The delivery decision must consume the result for the exact version being sent, so evidence from an earlier attempt cannot authorize a changed movie or hide a failed handoff.

**Consequences.** The artifact contract grows, and storage failure can block an otherwise playable movie. Recovery must regenerate or recover the correct result instead of substituting an unrelated successful check. The offline rendering example does not perform factual review; its drawing diagnostics serve a different purpose and cannot be promoted into fact-check acceptance evidence.
