# 0019 — Use an external encoder

**Context.** The renderer produces frames, but delivery requires a playable and seekable movie. The demo turns 480 frames at 30 fps into a 16-second video. An earlier batch produced no movies because the installed LGPL FFmpeg variant lacked libx264 and failed with Unknown encoder when encoding began.

**Alternatives.** One route bundles an encoder binary with the source distribution. The other installs external FFmpeg with the required GPL/libx264 capabilities and streams frames into it. Bundling controls the binary more directly, but adds platform packaging and binary redistribution work; external installation keeps that dependency explicit in the runtime setup.

**Decision.** Choose external FFmpeg with libx264 available. Verify the encoder capability before a batch, not merely the presence of the executable. Keep frame streaming and audio muxing on the same rendering path, and inspect the completed movie’s frame count, duration and dimensions to verify that encoding produced the expected artifact.

**Consequences.** The runtime installer must select a compatible build and account for its license terms. Different builds can change codec availability even when the command name stays the same. Encoder subprocesses also need cleanup on failure, since a job that stops reporting progress must not leave expensive media processes consuming memory indefinitely.
