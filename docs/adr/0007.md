# 0007 — Queue fairness

**Context.** Media jobs occupy workers much longer than admission checks, and failed renders can retain resources after a request ends. Orphaned rendering subprocesses consumed 1.2–1.4 GB each; running two episodes exhausted a 4 GB machine. A queue that considers only arrival order misses the resource pressure behind apparently unrelated failures.

**Alternatives.** One route admits every arrival immediately and allows expensive work to compete without explicit limits. The other separates inexpensive admission checks from scheduled media execution and bounds work in flight. Immediate execution reduces scheduling machinery, but it can turn a short burst into a machine-wide failure.

**Decision.** Choose explicit admission and fair queue service before rendering. Reject invalid work before it occupies a render slot, and limit active work using measured memory needs. Count surviving child processes when deciding whether capacity is available; a failed parent does not prove that its worker’s memory has been released.

**Consequences.** Bounded execution can increase waiting time, and fairness cannot make unequal jobs finish together. Queue state, cancellation and process cleanup must agree about when a slot is reusable. Raising concurrency is justified only after observing resource headroom, rather than as a response to users seeing a longer queue.
