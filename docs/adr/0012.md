# 0012 — Retain a fixed release

**Context.** A reviewed movie becomes difficult to explain if its input, renderer and evidence are replaced independently. The demo has a precise observable shape: 16 seconds, 480 frames, 1280×720 and 30 fps. Keeping only the movie would preserve what viewers saw while losing the information needed to investigate how it was made.

**Alternatives.** One route continually replaces the current artifact and relies on the latest code to explain earlier output. The other retains a versioned set of inputs, dependencies, movie and associated evidence. Continuous replacement uses less organizational effort, but it breaks the connection between a review and the bytes that review examined.

**Decision.** Choose a fixed release with its inputs and dependency information. Associate validation results with that same version. The earlier failure in which fact checking ran but its result was not saved establishes why an unaccompanied movie is insufficient: the delivery can succeed while the evidence required to accept it is absent.

**Consequences.** Retained versions consume storage and require explicit naming and lifecycle decisions. Corrections produce another version rather than silently changing the reviewed one. Consumers must compare the intended release identity when collecting artifacts, because matching duration and resolution alone does not establish that two movies contain the same instructional content.
