# 0004 — Bandwidth and concurrent playback

**Context.** Delivery capacity is shared by viewers, whereas the renderer produces a file once. The demo contains 480 frames at 1280×720 over 16 seconds. Frame count and resolution describe the workload, but the encoded file size determines how many bytes the delivery link must serve for each complete viewing.

**Alternatives.** One route chooses encoding settings only for visual fidelity and lets concurrent playback consume whatever bandwidth results. The other includes encoded size and available throughput in the delivery budget. The first is straightforward for a single viewer; the second accounts for multiple viewers competing for the same link.

**Decision.** Choose a bandwidth budget when selecting encoding settings. Measure the encoded bytes, divide by the 16-second duration to obtain average media throughput, and compare aggregate demand with measured link capacity. Preserve margin for bursts and startup rather than treating the average bitrate as a guarantee of smooth concurrent playback.

**Consequences.** Smaller encodings can blur labels or introduce artifacts around moving geometry. Capacity planning must therefore inspect instructional readability as well as transfer size. Additional viewers may still require more delivery capacity; reducing bitrate indefinitely is not an acceptable substitute when the lesson’s text and object relationships become hard to see.
