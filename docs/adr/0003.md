# 0003 — Playback response headers

**Context.** A completed video must be playable inside the browser, not merely retrievable as bytes. The demo is a 16-second H.264 movie at 1280×720 and 30 fps. Those media properties are necessary for delivery, but a response that instructs the browser to download can still defeat the intended viewing experience.

**Alternatives.** One route accepts the storage provider’s default delivery behavior. The other controls the delivery endpoint and its response headers. The default is simpler to connect, while explicit control makes inline disposition, media type and byte-range behavior part of the playback contract instead of incidental storage settings.

**Decision.** Choose a delivery endpoint that permits inline playback. Verify the headers on the actual movie response, including range requests used for seeking. Checking only a landing page or a successful whole-file download does not establish that the browser can start, pause and seek through the encoded result.

**Consequences.** Header control adds configuration that can drift independently from the encoded media. Caches and intermediaries must preserve the intended response behavior. Playback failures therefore need both media inspection and response inspection; rerendering the same 480 frames cannot repair an incorrect disposition header or broken range handling.
