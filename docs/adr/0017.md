# 0017 — Fixed input for offline execution

**Context.** A reader should be able to exercise drawing and encoding without acquiring model credentials. The included storyboard has two scenes of 8 seconds each, producing 16 seconds at 30 fps. Its fixed declarations make the relation between input, action timing and the resulting 480 frames directly inspectable.

**Alternatives.** One route requires a generation service to create input before every demonstration. The other supplies a manually authored storyboard and adapts its input model at the demo entry. Service-generated input exercises more of an application, but it also introduces network access, credentials and changing content before the renderer can be inspected.

**Decision.** Choose fixed input for offline execution. The example calls the existing renderer with explicit scene data and retains encoded-action checks. The second scene makes the block disappear through the existing opacity action, giving the movie a temporal behavior that can be verified after encoding rather than inferred from a still image.

**Consequences.** This boundary excludes script generation, speech synthesis and factual review from the executable example. The audio track is silent and narration appears as captions. Editing the board can still fail geometry or glyph validation; fixed input removes service setup, but it does not promise that arbitrary instructional scenes satisfy the renderer’s contracts.
